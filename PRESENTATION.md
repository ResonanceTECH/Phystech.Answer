# «Физтех.Ответ» — презентация на 5 минут

Структура питча: **9 слайдов, ~300 секунд** (4,5–5 мин речи + запас на вопросы).
Формат каждого слайда: что на нём / что говорить вслух / тайминг.

**Общие принципы:** один слайд — одна мысль; на слайде только крупные тезисы
(≤ 6 строк), детали — в речи; каждый слайд после второго — со скриншотом
или схемой, голый текст не оставлять.

---

## Слайд 1 — Титул (~10 сек)

**На слайде:**
- Логотип / название: **Физтех.Ответ**
- Подзаголовок: *Навигатор сотрудника по внутренним регламентам МФТИ*
- Строка: [хакатон / трек / номинация] · Команда: Daria, Victoria
- В углу — скриншот интерфейса чата (или вся страница целиком мелко)

**Говорим:** «Мы — Физтех.Ответ. Система, которая отвечает на рабочие
вопросы сотрудников по внутренним регламентам МФТИ — с источниками,
без выдумок и без утечки данных за контур».

---

## Слайд 2 — Проблема (~45 сек)

**На слайде:**
- Заголовок: *«Ответ на вопрос — в горе приказов, регламентов и сканов»*
- 4 тезиса:
  - У сотрудника вопрос («Как забронировать концертный зал?») — ответ
    в одном из 20+ актов: PDF, DOCX, XLSX, часть — сканы без текстового слоя
  - Регламенты живые: редакции, отменённые приказы, противоречия
  - Ручной поиск: часы времени + риск действовать по **утратившему силу** акту
  - Внешние LLM недоступны: внутренние документы конфиденциальны

**Говорим:** «В МФТИ регламенты — это десятки приказов и приложений.
Сотруднику нужно не просто найти документ, а понять, **какая редакция
действует сейчас**. Ошибка здесь — это нарушенный регламент. А отдать
базу во внешний ChatGPT нельзя — это внутренние документы».

---

## Слайд 3 — Решение (~40 сек)

**На слайде:**
- Скриншот интерфейса: вопрос → ответ со ссылками [1] [2]
- 4 буллета:
  - Вопрос **обычным языком** → краткий ответ + пошаговый порядок действий
  - Каждое утверждение — кликабельная ссылка на **документ и пункт**
  - Предупреждает об изменениях редакций и противоречиях
  - Честное **«в базе нет информации»** вместо выдуманной процедуры
- Нижняя плашка: *Работает полностью локально — данные не покидают контур*

**Говорим:** «Пользователь пишет как человеку: „как командировать
сотрудника?“. Система находит нужные приказы, собирает ответ и
обязательно показывает, откуда он взял каждый факт — пункт и документ.
Если ответа в базе нет — она так и говорит, а не фантазирует».

---

## Слайд 4 — Как это работает (~55 сек)

**На слайде:** схема конвейера (6 блоков, стрелки):

```
Вопрос → Декомпозиция → Гибридный поиск → Реранкинг → Генерация → Проверка
           (составные      BM25 + bge-m3     H2O-4B    со ссылками   цитат
            вопросы)      + RRF            «судья»
```

Под схемой 3 маленькие подписи:
- «нет доказательств → честный отказ, без галлюцинаций»
- «+ подтягиваем изменяющие акты — актуальная редакция»
- «каждый ответ хранит трассировку: что искали, что нашли, сколько заняло»

**Говорим** (ключевые идеи, не пересказывать схему):
- «Декомпозиция: „еду на конференцию, а потом проведу семинар“ — это два
  вопроса. Один запрос уводит поиск в сторону».
- «Гибридный поиск: BM25 с русским стеммером точно ловит термины
  („ФЛС“, „794-1“), векторы bge-m3 — перефразировки („сломался ноутбук“
  → регламент техподдержки)».
- «Решение „есть ли ответ в базе“ принимает реранкер-модель, а не порог
  по косинусной близости — поэтому перефразированный вопрос не отклоняется
  ошибочно, а чужой — не проходит».
- «Генерация при temperature=0, каждая фраза со ссылкой [n]. Потом
  автоматическая проверка цитат: выдуманные ссылки удаляются, ответ
  без ссылок понижается до „частичного“».

## Слайд 5 — Примеры / демо (~60 сек)

**На слайде:** 3 карточки (скриншоты реальных ответов):

1. **Процедура** — «Как забронировать Концертный зал?» →
   ответ: служебная записка на имя нач. КМО на kmo@mipt.ru;
   пошагово: уточнить даты у КМО → согласовать техсотрудников →
   записка через 1С:Документооборот. Источники: регламент № 3897-1
   от 01.09.2025, п. 2.5–2.7 и 3.6–3.8
2. **Редакция** — «Действует ли приказ № 1465-1?» →
   «Нет, утратил силу по приказу № 5990-1 от 03.11.2026» + ссылка
3. **Вне базы** — «Как оформить ежегодный отпуск?» →
   «В базе нет информации» — без выдуманной процедуры

**Говорим:** «Три кейса показывают три режима: полноценная процедура
с шагами, контроль актуальности редакций и честный отказ. Если останется
время — покажем живое демо в интерфейсе».

---

## Слайд 6 — Технологии (~30 сек)

**На слайде:** две колонки-чипы:

| Слой | Стек |
|---|---|
| Frontend | React 19, TypeScript, MUI, FSD-архитектура |
| Backend | Go, PostgreSQL, очередь задач, разбор PDF/DOCX/XLSX |
| ML-конвейер | Go (stdlib), собственный русский стеммер Snowball |
| Модели | bge-m3 (эмбеддинги) + qwen3.5:4b (генерация) в Ollama; H2O-Lightning-4B — реранкер через llama.cpp |
| OCR | Tesseract 5 (rus+eng) — 5 сканов, 46 страниц |
| Инфра | Docker Compose — весь стенд одной командой `docker compose up` |

**Говорим:** «Всё локально, без внешних API: модели крутятся в контейнерах.
Единственная внешняя зависимость — на первом запуске скачиваются модели,
потом стенд работает офлайн. Русский стеммер мы написали сами — на
stdlib, чтобы не тянуть зависимостей».

---

## Слайд 7 — Качество: цифры (~30 сек)

**На слайде:** крупные цифры + сноска:

- **100%** — верный статус ответа на всех **39 размеченных вопросах**
- **97%** — нужный документ находится гибридным поиском (BM25: 94%)
- **0%** — ложных отказов на вопросах вне базы
- **15 с** — медианная задержка ответа **на CPU, без GPU**

Сноска мелко: *Набор: процедуры, факты, перефразировки, составные
вопросы, вопросы о редакциях, 5 вопросов вне базы, мусорный ввод.
Полные отчёты — в репозитории (eval/)*

**Говорим:** «Мы не просто собрали RAG — мы его измерили. 39 вопросов
с разметкой: документы, пункты, ожидаемые статусы. Статус ответа
угадан во всех 39 случаях; вопросы вне базы отклоняются все и без
ложных отказов. Да, 15 секунд на CPU — это медленно; на GPU будут
единицы секунд, и это следующий шаг».

## Запасные слайды (если спросят / останется время)

- **«Почему не просто ChatGPT?»** — конфиденциальность (контур),
  галлюцинации без ссылок, устаревшие редакции, цена за запрос.
- **«А если модель выдумает?»** — проверка цитат + порог доказательств +
  temperature=0 + статус partial вместо answered.
- **«Что если документы меняются?»** — импорт по SHA-256 при старте,
  новые редакции переиндексируются, изменения актов учитываются
  автоматически.
- **Скриншот «Как найден ответ»** — трассировка в UI: режим поиска,
  подвопросы, изменяющие акты, время этапов.
